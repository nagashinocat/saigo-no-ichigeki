# 街破壊 第2弾の直し 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 持ち主が遊んで出した直し（設計書 11章）を入れる。
**Spec:** `docs/superpowers/specs/2026-11-20-machi-hakai-design.md`（11章）
**Architecture:** 既存の views.js（上空カメラと追従）、cinematic.js（大きな一発の演出）、sphereDeform.js（穴）、cityView.js/style.js（地面）、enemyView.js / enemies.js（軍勢）、destruction.js / debris.js（破片）に手を入れる。

## Global Constraints
- 縦画面（390×844）が主。街は上65%、手は下35%。
- 中くらいのAndroidで30fps以上を目標に、毎フレームの重さを増やしすぎない。
- 画面の文言は日本語。見た目はすべてオリジナル（既存の作品の乗り物・衣装・人物に似せない）。
- 既存のテストを弱めない。目で確かめる作業は scripts/snap.mjs（?debug と __debug の段送り）で撮って見る。

## Review Focus
1. 2回目以降の爆発でも、主人公と広場が画面の中心に見え続けること。
2. 小さな一発を連打しても、カメラが遠くへ行ったり来たりして酔わないこと。
3. 瓦礫を残しても、60秒のあいだ重さが増え続けないこと（数に上限）。
4. 空飛ぶ軍勢でも、掴む・倒される・目が映る一拍がこれまでどおり働くこと。

---

### Task R1: 上空カメラを近づけ、爆発は「近く→全体」で見せる
- `CITY_CAMERA` を近づける（目安: 高さ 150〜180m、後ろ 150〜180m。広場と軍勢の輪が今より大きく見える）。cityCamera.test.js の見えるかのテストは新しい位置で通す（基準は下げない。通らなければビルの高さ制限や角度で合わせる）。
- 通常の爆発（大きな一発の演出以外）のカメラ: 弾けた直後は近いまま速く広がる爆発の前線を見せ、約0.6秒後に、球の全体（最終の半径）が画面に収まる遠めの位置へなめらかに引く。爆発が終わったら約1秒保って、近い上空カメラへ戻る。小さな一発（半径が一定以下、目安60m）は引かない。連打で行ったり来たりしないよう、戻る途中に次の爆発が来たら、その場から続ける。
- 大きな一発の演出（cinematic）は、追われて引く場面の最後に、全体が見える遠めの構図で一度止めてから、近い上空カメラへ戻る。
- 位置の計算は純粋関数にし、テストを書く（引く時刻、全体が収まる距離、小さな一発は引かない、連打で跳ばない）。
- 目で確認: 小・中・最大の一発を 390×844 で、弾けた直後・0.6秒後・全体が見えたところで撮る。

### Task R2: 主人公の足元を残し、爆心地に瓦礫を残す
- 主人公は元の地面の高さ（y=0）に留まる。穴の形（craterDepth）は、主人公の足元の半径（目安 4m）だけ元の高さを残す「柱」にする。柱の側面は岩肌で、上は広場の床の一部が残る。地面のシェーダーと JS の groundHeight を同じ式に揃え、既存の GLSL/JS 一致テストを足す。
- 上空カメラと演出のカメラは主人公（y=0）を見続ける。2回目以降の爆発でも画面が穴に沈まない。
- 瓦礫: 破片が穴の底や斜面に落ちて止まったら、土煙に変えて消すのではなく、静かな瓦礫として残す（1つの InstancedMesh、上限は段ごと: high 3000 / mid 1500 / low 600。上限を超えたら古いものから土煙にして消す）。建物ごとに数個の大きな塊も残す。止まった瓦礫は毎フレーム動かさない。
- テスト: 柱の高さ（r<4m で 0）、瓦礫の上限、止まった瓦礫は更新されない。
- 目で確認: 1回目と2回目の爆発のあと、上空から主人公が柱の上に立ち、穴の底に瓦礫が積もっているのを 390×844 で撮る。

### Task R3: 軍団を空飛ぶバイクに乗せる
- 軍勢は1人乗りの浮遊バイク（オリジナルのデザイン: 前後に推進の光、低い車体）に乗り、地面や穴から一定の高さ（目安 2〜4m、穴の上でも浮く）で近づく。わずかに揺れ、近づくほど速度を落とす。
- 掴むときはバイクを主人公の横に止め、乗り手が手を伸ばす姿勢にする。爆発で倒れたら、バイクごと外へ吹き飛ぶ。
- ビルの陰の影絵と目印、目が映る一拍（バイザーの目）、物理の判定（enemies.js の距離）はこれまでどおり働くこと。浮く高さは見た目だけで、判定の距離は水平で測る。
- テスト: 浮く高さが穴の上でも保たれる、掴むときの位置。
- 目で確認: 通常の上空画面で近づく軍勢、掴む軍勢、大きな一発の目の一拍を 390×844 で撮る。

### Task G1: 遊び方の作り直し（1発で終わる・小爆発ボタン・増える軍勢・時間切れ）
- 仕様 12章の「遊び方」。game.js / charge.js / reserve.js / enemies.js / config.js / input と HUD を作り直す。
- 力のモデル: 長押しの間だけ力が貯まる（上限あり）。離すと大きな一発（貯めた量で半径が決まる、最大で街の端まで）を放ち、ゲームの進行は終わり（以後は演出→結果）。指を離さない限り放たれない。
- 小爆発ボタン: 画面右下などに置くボタン（長押しの指とは別の指）。押すと貯めた力の一定量（目安: 上限の8%）を使い、主人公のまわり半径20〜30mの小さな爆発で軍勢を払う。力が足りなければ押せない（見た目で分かる）。押した分は大きな一発の半径から減る。小爆発でもビルは壊れて破壊額に入るかは設計者の判断（入れない: 結果は大きな一発の破壊額のみ）。
- 押す指の扱い: 長押し用の指と小爆発ボタンの指を区別する（press tracker を、ボタン上の押下はボタン、それ以外は長押し、に分ける）。Review Focus 2 のスマホの扱いは保つ。
- 軍勢は時間とともに増える（湧く速さが60秒で目安3〜4倍）。掴まれると貯めた力が減る。
- 時間切れで放っていなければ 'over' の理由 'blackhole'（演出は G5）。放ったら 'over' の理由 'released'（結果は大きな一発の破壊額）。
- 既存のテストは新しい規則に合わせて書き換え、規則ごとにテストを足す。HUD: 貯めた力の量（手の帯の上の線を「貯めた力」に）、残り時間、小爆発ボタン。

### Task G2: 上空カメラをさらに寄せる
- 仕様 12章: 広場を囲むビル8つ（最初の一周の街区）がしっかり入り、その外側は切れるくらい。軍勢がはっきり見える。cityCamera.test.js の見えるかのテストは、新しい距離に合わせて対象（広場と最初の一周、軍勢が湧く範囲のうち画面内に入る部分）を見直す。軍勢の湧く距離（spawnDist）も画面に入るよう見直してよい。

### Task G3: 最後の一発の演出（体感時間のガラス・宇宙・横一線の光）
- 仕様 12章の絵コンテ 1〜5。cinematic.js を作り直す。ガラスの一拍は「爆発の前線で砕けたビルの窓ガラス」に、軍勢の一人の目が映る形にし、体感時間のスロー（極端な時間の伸び、心臓の音）で見せる。宇宙のカメラは地球の丸み・夕暮れの境目・雲・衝撃波の輪。最後は横一線の光が細くなって消える。迫力と格好よさが最優先。重さは段ごとに抑える。

### Task G4: リプレイと結果へのつなぎ
- 仕様 12章の絵コンテ 6〜7。最後の一発の直前の街の状態を覚えておき、爆発を何度も見せ直せるようにする（同じシードで決まった結果になる）。4つのカットを、黒い帯（シネマスコープ）と時間の伸び縮みで見せる。画面タップで飛ばせる。そのあと結果画面。

### Task G5: ブラックホールの結末
- 仕様 12章「時間切れの結末」。手の中の球がつぶれ、両手が引き込まれ、重力レンズのゆがみ、街が渦を巻いて吸い込まれ、黒い球と光の輪、暗転、「ブラックホールになった」。
