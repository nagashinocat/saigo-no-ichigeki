# 街破壊3Dゲーム（仮題）設計書

日付: 2026-11-20
状態: 持ち主の承認待ち

## 1. 何を作るか・なぜ

手の中で力を貯め、離すと自分を中心に球状の爆発が膨らんで街を壊していく、ブラウザで遊べる3Dゲーム。

- **芯は「壊すのが気持ちいい」こと**（持ち主の決定）。怖さや物語より、破壊の爽快感を優先する。
- **グラフィックの綺麗さ・細かさが気持ちよさを大きく左右する**（持ち主の考え）。
- 持ち主が**特にこだわる4点**: 手の中の力、破壊のアニメーション、爆発、手の形。
- 雰囲気は「手の中で力が爆ぜる」系の有名作品から着想を得ているが、**キャラクター・力の見た目・名前はすべてオリジナル**にする。元の作品の固有の意匠（特定の登場人物、ロゴ、セリフ、特徴的な衣装やバイクなど）は使わない。

## 2. 目標・やらないこと・失敗の定義

**目標**
- 1回遊ぶと、街ひとつをまるごと吹き飛ばせる規模感（持ち主の決定）。
- 破壊額を競う、短く何度も遊びたくなるゲーム（持ち主の決定）。
- スマホとPCの両方のブラウザで遊べる（持ち主の決定）。

**やらないこと（今回の範囲外）**
- 主人公の移動。主人公は動かず、爆心地は常に主人公の位置（持ち主の決定）。
- 物語モード、街の育成、複数ステージの進行（遊びの形は「制限時間で破壊額を競う」に決定済み）。
- オンラインランキング（持ち主の決定ではなく範囲を絞る提案。スコアの共有は画像やテキストのSNS共有で代える。後で足せるようにしておく）。

**失敗の定義（動いても失敗とみなすもの）**
- 爆発や崩壊がカクつく。滑らかさが失われると気持ちよさが消える。特にスマホで重要。
- 壊れ方が毎回同じに見え、作り物っぽい。
- 手や力の表現が安っぽく、貯める行為そのものが楽しくない。
- 元の作品の模倣に見える。

## 3. 遊びの仕組み

### 3.1 1回の流れ
1. 開始。主人公は街の中心付近に立っている。
2. 制限時間（目安60秒。数値は調整対象）の中で、貯める→放つを繰り返す。
3. 謎の軍勢が四方から主人公に向かってくる（持ち主の決定）。
4. 時間切れで終わり、破壊額が確定する。または力の器が空になるとゲームオーバー。
5. 結果画面で破壊額を表示し、SNSで共有できる。

### 3.2 力の器と貯め（A案、持ち主の決定）
- 手の中に、命でもある**「力の器」**がある。器の力は時間とともに**自然に満ちていく**。
- **長押し**で器から力を引き出し、手の中で膨らませる（貯め）。**離す**と、引き出した分を使って爆発する。
- 貯めた量が多いほど、爆発の球が**大きく、遠くまで**届く（持ち主の決定）。
- 大きく放つほど器が薄くなり、掴まれたときに危なくなる。これが「どこまで貯めるか」の駆け引き。

### 3.3 軍勢
- 力を奪おうとする謎の軍勢が、四方から主人公に近づいてくる（持ち主の決定）。
- **掴まれると器の力が減っていき、0になったらゲームオーバー**（持ち主の決定）。
- 爆発に巻き込まれた軍勢は吹き飛ぶ。小さく放てば近くの敵を払えるが、破壊額はあまり伸びない（提案）。
- 軍勢の見た目と種類は未定（下記「残っている決めごと」参照）。

### 3.4 破壊の進み方（提案）
- 爆心は常に主人公なので、近くの建物から先になくなる。まだ残っている遠くの街を壊すには、毎回もっと大きく貯める必要がある。そのため、60秒の中で一発の大きさが自然に上がっていく。
- 最後のほうには、街の端まで届く特大の一発を放てるよう数値を調整する。

### 3.5 破壊額
- 建物・車・街灯などそれぞれに金額があり、壊した分が加算される。
- 一度に大量に壊すと、ボーナスの倍率がつくなどの「大きい一発ほど得」な仕組みにする（提案。細かい式は作る人に任せる）。

## 4. 画面と演出

### 4.1 2画面構成（持ち主の決定）
- 「周りの街」と「自分の手の中」を同時に映す。
- 配置の目安（提案。スマホ縦持ちを基準に、PCでは横に並べる等の調整は作る人に任せる）:

```
┌─────────────────────┐
│   周りの街（メイン） │
│   ビル・軍勢         │
├──────────┬──────────┤
│ 手の中   │ 破壊額    │
│ 力が膨らむ│ 残り時間  │
│          │ 力の器    │
└──────────┴──────────┘
```

### 4.2 手と力（重点）
- 貯め具合は、ゲージではなく**手の変化で見せる**（提案）。指がこわばり、光が漏れ、限界近くで手そのものが震える。
- 手の形は、指の関節まで動かせる手のモデルを使う。貯める段階ごとに手の構えが変わる。
- 手の中の力は球状の光で、貯めるほど膨らみ、揺らぎ、周囲の空気をゆがませる。

### 4.3 放つ瞬間のカメラ（持ち主の決定）
- 長押しを離すと、カメラが手から引いていき、爆発の様子が**いちばん格好よく見える位置**を割り出して移動する。
- そこで**一瞬止まって（スローや静止）から爆発**が広がる。
- 一瞬止まる中に、軍団の一人の目がガラス等に映り込む緊迫の一拍を入れる（8章参照）。
- 「いちばん格好いい位置」は、球の表面がビルを飲み込む瞬間が画面に大きく入る角度を基本にする（提案）。具体的な選び方は作る人に任せるが、毎回同じ角度にならないようにばらつきを持たせる。
- この演出の間は**制限時間を止める**（提案）。格好いい場面が損にならないようにするため。

### 4.4 爆発と破壊（重点）
- 爆発は**主人公を中心に球状に膨らむ**（持ち主の決定）。
- 球に触れたものは**外側へ押し出されていく**のが基本（持ち主の決定）。
- **球の中心近くでは、光に溶けて消える様子も少し見せる**（持ち主の決定）。
- 押し出された破片は、遠くへ行くほど土煙や粉に変わって薄れていく（提案。見た目のためと軽さのため）。
- **地面も球の形にえぐれる**（持ち主の決定、2026-11-20追記）。球が広がるのに合わせて、地面が球面のすり鉢状にえぐれ、上から見て球だとわかるようにする。
- **ビルは球の線に沿ってゆがみ、押しつぶされるように壊れる**（持ち主の決定、2026-11-20追記）。ブロックが飛んでいくだけに見えないよう、球の表面が当たった部分から球の壁に押し付けられるように曲がり・ひしゃげ、そのあと細かい破片と土煙になって外へ流れる。
- 画面効果として、光のにじみ、熱による空気のゆがみ、衝撃波、土煙、画面の揺れを使う。

## 5. 作り方

### 5.1 検討した方法

| 方法 | 長所 | 短所 |
|---|---|---|
| **A. Three.js＋あらかじめ割ったビル＋手前だけ軽い物理計算**（採用） | 軽く、スマホでも滑らか。壊れ方を演出として作り込める。GitHub Pagesにそのまま置ける | ばらつきを作り込む手間がかかる |
| B. Babylon.js＋全面的な物理計算 | 崩れ方が毎回自然に変わる | 街ひとつ分の破片を物理で動かすとスマホでカクつく。「滑らかさ」と衝突する |
| C. Unityで作りブラウザ向けに書き出す | 見た目の上限が最も高い | 読み込みが重く、スマホのブラウザで不安定になりがち |

**Aを採用**（持ち主が選択）。持ち主から「球が膨らむので物理計算はあったほうがいいか、軽いままなるべく格好よく見せたい」という問いがあり、全面的な物理ではなく、演出を主にして手前だけ物理を使う形で合意した。

### 5.2 Aの中身
- **描画**: Three.js。画面効果（光のにじみ等）はポストプロセスで足す。
- **ビル**: あらかじめ数十個の破片に分けたモデルを用意する。球の表面が届いた瞬間に、破片を外向きに演出として飛ばし、崩れ落ちるよう動かす。何百棟ぶんでも軽く動くことを優先する。
- **物理計算**: 一瞬止まるカメラの画面に映る**手前の破片だけ**を、軽い物理エンジン（候補: Rapier や cannon-es。選択は作る人に任せる）で動かす。上限の目安はPCで数百個、スマホで数十個。
- **画質の切り替え**: 中身は一つで、端末の性能に合わせて破片数・粒子数・画面効果を自動で切り替える（提案）。スマホでは細かさより滑らかさを優先する。
- **操作**: 押しっぱなしで貯め、離して放つ。指でもマウスでも同じ（提案）。
- **公開先**: GitHub Pages（持ち主の他の作品と同じ。提案）。

## 6. 作る人に任せること
- 数値の調整全般（制限時間、器の回復速度、貯めの速度、球の大きさ、軍勢の速さと数、建物の金額）。目標は「60秒で街ひとつを吹き飛ばせる」「大きく貯めるほど危ないが得」の両立。
- 「いちばん格好いいカメラ位置」の選び方の具体的な方法。
- 物理エンジンの選択、端末性能の判定方法。
- 街の作り方（手で配置するか、自動生成するか）。
- コードの構成。

## 7. 設計者の判断で決めたこと（チェックで出た点）
- **動作の基準**: 3年ほど前の中くらいの性能のAndroidで、安定して30fps以上。PCでは60fps。2画面とも毎フレーム描く前提で、破片数や画面効果の上限を決める。
- **一瞬止まる演出は大きな一発だけ**: 貯めが一定以上のときだけカメラ演出と時間停止を入れる。小さく払う一発は手元の画面だけで即座に爆発させ、テンポと時間停止の悪用を防ぐ。境目の値は調整対象。
- **自滅はしない**: 1回で引き出せる量には上限があり、器には必ず少し残る。器が0になる原因は掴まれることだけ。限界が近いと、手の震えや光のちらつきで知らせる。
- **素材**: 手は無料で使える(CC0等)指の関節まで動くモデルを基にし、構えと光の表現はこちらで作り込む。ビルと破片の分割はコードで自動生成する。費用はかけない前提。
- **音**: 範囲に含める。貯めの唸り、放つ瞬間の無音、爆発と崩落の音。スマホは最初のタップで音を有効にする。

## 8. チェック後に持ち主が決めたこと
- **作風は「写実的なアニメ調」**（持ち主の決定）。形・光・質感は写実寄りで、色づかいや光のにじみ、輪郭の見せ方はアニメ映画の背景や作画のように描く。具体的には、建物や街並みは細かく描き込み、光と影は強めにくっきりさせ、爆発の光は鮮やかに大きくにじませる（解釈は設計者の提案）。
- **軍勢は兵士風の謎の軍団**（持ち主の決定）。顔はほぼ見えないが、目だけは見える装備にする（下の演出のため。設計者の提案）。
- **爆発前の緊迫の一瞬**（持ち主の決定）: 大きな一発の一瞬止まる演出の中で、軍団の一人の目が映ってから爆発する。例として、まず小さく弾けてビルのガラスが飛び、その飛んでくるガラスに軍団の目が映り込み、そこから本爆発が広がる。毎回同じにならないよう、映り込む物（ガラス、ヘルメットのバイザー、水たまり等）や映る人を変える（設計者の提案）。
- **普段のカメラ**（持ち主の決定）: 手のアップの画面と、周りを見渡せる上空からのカメラの2つ。
- **街の人**: 持ち主の回答がなかったため、設計者の判断で「すでに避難したあとの街」とする。人が吹き飛ぶ描写はせず、SNSで共有しやすくする。

## 9. 持ち主の追加要望（2026-11-20 14:32）
- **両手で構える**: 両手の手のひらを、間に浮かぶ力の球に向ける。指は力を込めて開き、こわばらせる（参考画像は構えの雰囲気だけ取り入れ、絵はまねない）。
- **手の画面のカメラは主人公自身の目**: 自分の両手を見下ろす一人称の視点。
- **大きな一発の流れ**: 離す → 両手が近づいて組み合わさる → 画面全体が真っ白 → カメラが主人公の目から後ろへ引いていく → 時間が止まり、ガラスに軍団の目が映る → 時間が動き出し、追ってくる爆発を見せながらカメラが引き続ける → 上空のカメラへ戻る。
- **爆発の速さ**: じわじわゆっくり始まり、ある瞬間に弾けるように一気に加速する。カメラも爆発の速さに合わせて引く。
- 設計者の判断: 演出の間は2画面ではなく画面全体を使う。小さな一発は、両手が素早く組み合わさって弾けるだけで、白くなる演出や時間停止は入れない。

## 10. 画面の配置の変更（持ち主の決定、2026-11-20 16:04）
- 縦画面が基本。上が上空の街、下の帯を全幅で手の画面にする（両手が横いっぱいに入る）。
- 破壊額・残り時間・力の器は、街の画面の上に小さく重ねて表示する（HUD の専用の枠はなくす）。
- 設計者の判断: PCなどの横長の画面でも同じ「上が街・下が手」の並びにする。

## 11. 遊んでみての直し（持ち主の決定、2026-11-20 17:55）
- **上空カメラを近づける**: 今（高さ280m・後ろ260m）より近く。街と軍勢がもっと大きく見えるようにする。
- **爆発のカメラは「いいとこ取り」**: 速く広がる爆発を、最初は近くで迫力をもって見せる。少したったら、爆発の全体が見える遠めのカメラへ移る。そのあと通常の上空カメラへ戻る。
- **主人公の位置は変わらない**: 1回目の爆発で穴ができても、主人公は元の地面の高さに留まる。2回目以降も画面が穴や瓦礫に埋もれない（設計者の判断: 主人公の足元だけ元の地面が柱のように残る）。
- **軍団は空飛ぶバイクのような乗り物に乗る**: 見た目は既存の作品に似せないオリジナル。穴の上でも浮いて近づける。
- **爆心地に瓦礫が残る**: 穴の底や斜面に、壊れた建物の瓦礫が積もって残る。まっさらにしない。

## 12. 遊び方の作り直しと最後の演出（持ち主の決定、2026-11-20 18:39）

### 遊び方
- **大きな一発は1回だけ。** 長押しで力を貯め、離すと大きな一発を放ち、そこでゲームが終わる。その一発の破壊額が結果になる。
- **小爆発ボタン**: 画面のボタンを（もう片方の指で）押すと、貯めている力を少し使って主人公のまわりに小さな爆発を起こし、軍勢を払う。
- **軍勢は時間がたつほど増える。** 掴まれると貯めた力が減る。
- **制限時間は60秒。** 60秒たっても放っていなければ、主人公自身がブラックホールになり、すべてを飲み込んでゲームオーバー（設計者の判断: 破壊額はつけない）。
- 上空カメラはもっと寄せる。広場を囲むビル8つがしっかり入り、その外側は切れるくらい。軍勢がはっきり見える。

### 最後の一発の演出（設計者の絵コンテ。持ち主の要望: 超一流の演出家として、迫力があって格好いい演出）
1. 離す → 両手が組み合わさる → 画面全体が真っ白。
2. 軍勢の一人の体感時間: 爆発の前線がビルに届き、窓ガラスが砕ける。時間がほぼ止まり、宙に浮いたガラス片に軍勢の一人の目が映る（極限に集中して体感時間がスローになった状態の表現）。目がゆっくり見開き、迫る光が瞳に映る。音は心臓の鼓動だけ。
3. 時間が戻り一気に弾ける。追ってくる爆発からカメラが引く。
4. 宇宙からのカメラ: 夕暮れの地球の丸みの上で、光の半球がふくらみ、衝撃波の輪が雲の上を走る。
5. 半球が地平に沿って押しつぶされ、横一線の光になり、細くなって消える。無音のあと、低い地鳴り。
6. リプレイ: 通りから見上げた光の壁／前線に沿って横へ流れるカット／真上から広がる穴／光の中心に立つ主人公の影。
7. 結果画面。

### 時間切れの結末（ブラックホール）
手の中の球が内側へつぶれ、両手が引き込まれる。画面がゆがみ（重力レンズ）、街が渦を巻いて中心へ吸い込まれ、黒い球と光の輪だけが残る。暗転して「ブラックホールになった」でゲームオーバー。
